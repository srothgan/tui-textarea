# Recording Examples

The crossterm example GIFs are generated by scripted terminal sessions inside Docker. The workflow pins the Rust and VHS container images, compiles Linux release binaries, replays the interactions in `recordings/*.tape`, and writes the finished GIFs directly to `assets/`.

## Requirements

- Docker Desktop or another Docker installation configured for Linux containers.
- Docker Compose v2, available through `docker compose`.

No local Rust, VHS, ttyd, ffmpeg, browser, or screen recorder installation is required.

## Generate Recordings

Build the recording image and generate the complete set from the repository root:

```powershell
docker compose --file recordings/compose.yml build
docker compose --file recordings/compose.yml run --rm recordings
```

Generate a single example after the image has been built:

```powershell
docker compose --file recordings/compose.yml run --rm recordings wrap
```

The container discovers every `recordings/*.tape` file except `common.tape`, so adding a focused example only requires adding its tape and ensuring the Docker image contains its compiled binary. Each tape must write `assets/<example_name>.gif`.

## Capture Profiles

Every recording uses the same 1200 px width, DejaVu Sans Mono font, font size, colors, and frame rate. Heights vary with the content so compact forms do not carry the empty space required by full-screen editor examples.

| Example | Terminal size | GIF size |
|---------|---------------|----------|
| `minimal` | `120x18` | `1200x360` |
| `editor` | `120x24` | `1200x480` |
| `single_line` | `120x10` | `1200x200` |
| `split` | `120x14` | `1200x280` |
| `variable` | `120x16` | `1200x320` |
| `vim` | `120x16` | `1200x320` |
| `popup_placeholder` | `120x12` | `1200x240` |
| `password` | `120x10` | `1200x200` |
| `wrap` | `120x20` | `1200x400` |
| `undo_coalescing` | `120x12` | `1200x240` |

The source width is intentionally larger than the README display width so text stays sharp on high-density screens.

## Repository Layout

| Path | Purpose |
|------|---------|
| `recordings/Dockerfile` | Builds the crossterm examples and the pinned VHS runtime. |
| `recordings/compose.yml` | Mounts the repository so generated GIFs are written back to `assets/`. |
| `recordings/common.tape` | Defines shared font, width, frame rate, and terminal environment settings. |
| `recordings/<example>.tape` | Defines one deterministic example interaction and its output path. |
| `recordings/fixtures/` | Contains stable input files required by recorded examples. |
| `recordings/record.sh` | Discovers tapes, invokes VHS, and verifies each expected output exists. |
| `assets/` | Contains the generated GIFs referenced by the README. |

The `termion` and `termwiz` examples are excluded because the recorded showcase targets the default crossterm backend.

## Review Checklist

Before committing regenerated assets, verify that:

- Every GIF begins on a stable rendered frame and ends without terminal startup or teardown.
- Every GIF has a width of 1200 px and the height declared in the capture profile table.
- Keystrokes are deliberate and the demonstrated behavior is understandable without narration.
- Unicode, colors, borders, cursor cells, and masked characters render correctly.
- The README contains a local `./assets/<example_name>.gif` reference for every recorded example.
- `git diff -- CHANGELOG.md` remains empty because historical release recordings are not part of this workflow.

Commit tape or example changes separately from regenerated binary assets when practical so code review remains clear.
